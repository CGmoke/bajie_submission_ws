# 题目三 · 在 Isaac Sim 中触碰玩具

> 解法说明与设计取舍。三件玩具的触碰在同一轮运行里完成，数值与日志都能在作品目录内回溯。

## 一、这道题要交什么

在 Isaac Sim 4.5 里打开官方场景、接好 ROS 2 Bridge，按输入给的底盘与玩具世界位姿，让机械臂对魔方、恐龙、软玩具各碰一次。碰完报告十个关节的实测值，以及夹爪和玩具两处的位姿。

| 项目 | 内容 |
|---|---|
| 题号 | 题目三 |
| 源码 | `src/question3_project/`（`run_touch.py` 主程序，`touch.py` 规划与判定，`bridge.py` 桥接，外加启动器与容器） |
| 输入 | `inputs/q3_demo_input.jsonl`，三个测例 `touch_toy_1/2/3` |
| 作答 | `answers/q3_demo_output.jsonl`，三行 |
| 演示 | `video/q3_touch.mp4` |

难点不在「让机械臂动起来」。难的是让评审相信：它真的碰到了，而不是擦过去、也不是把玩具顶飞了。

## 二、题面四条对着做

| 题面 | 做法 |
|---|---|
| 开官方场景，配 ROS 2 Bridge | 场景只开一次，既有 OmniGraph 全部置 inactive，只留本题自建的桥接图。CPU PhysX，60 Hz 定步长 |
| 读底盘与玩具世界位姿，换到规划坐标系 | 底盘按 `base_footprint_in_world` 摆位，用内存里的 `FixedJoint` 锚住；规划在底盘系做，`T_base^toy = (T_world^base)^-1 · T_world^toy` |
| 每个测例从指定初始关节状态出发，独立规划并触碰 | 每例都从输入的初始状态起步、单独出路点；碰完不归位，直接从实测位姿接着够下一件 |
| 说明目标位姿处理、规划、控制、触碰判定 | 见下节四小节 |
| 输出三样东西 | `final_joint_state`、夹爪相对底盘位姿、玩具在 `objects_link` 里的位姿；三例全过才写文件 |

## 三、怎么做的

### 3.1 分四层，各管一段

场景层负责把世界摆对：一次开场景，关掉所有既有 OmniGraph，只留自己的桥接图；底盘用 `FixedJoint` 锚死，保证后面算 `base_footprint` 时脚下不会飘。

规划层在底盘系里算目标，用增量 IK 求十关节，再采样成十八个路点。接近姿态是两指张开、由上往下贴。

控制层把路点一条条发下去，等实测到位。手腕位置和速度连续四步稳住，才允许合指。

判定层决定这次算不算碰上，并把接触那一瞬的实测值留下来。

### 3.2 目标位姿怎么处理

输入给的是世界位姿，规划要的是底盘系。先求底盘在世界中的变换（带 180° 的朝向），左乘其逆，得到玩具在底盘系的位姿。夹爪在世界系里的位姿也一并留着，收尾时把玩具位姿换到 `objects_link` 系，要乘的正是它。

### 3.3 怎么规划

起点是当前实测关节位姿，不是规划值。用 `scipy.optimize.least_squares` 做增量 IK，关节空间的解按 smoothstep 采样成十八个路点，限位和速度在这一步就校验掉。

为什么起点要用实测？仿真里指令和到位之间总有偏差，从指令值出发规划，等于假装自己已经在想去的地方。误差会累积，越到后面越离谱。

### 3.4 怎么控制

路点逐条下发，等实测到位再发下一条。合指有个前置条件：手腕的位置与速度连续四个仿真步稳定。

这条限制不是多余的。腕还在走就合指，指尖位姿跟规划对不上，接触点会落在一个谁也没算过的位置。真要命的是，它还常常「成功」——PhysX 确实报告了接触，只是碰的地方不对。

### 3.5 怎么判定碰上

两条同时成立才算数。

物理上，PhysX 要报告同一根夹指与目标玩具之间存在带冲量的、非正分离的接触。几何上，接触点得落在玩具的可见网格上（`visible_surface=touch`），不能只是碰到碰撞外壳。

连续六个仿真步都成立才记录。第一次满足时先保持当前指令；连着六步没等到有效接触，才沿原方向微调，合指每次 0.003 rad、下探每次 0.25 mm，最多四次。合指类动作给玩具的位移上限是 2 mm；垂直下压是有意轻碰，放宽到 6 mm。中途出现非目标碰撞，直接中止。

### 3.6 三件玩具三种手法

形状差太多，一套参数必然有一件要失败。

| 测例 | 策略 | 手法 |
|---|---|---|
| `touch_toy_1`（魔方） | `cube_side` | 合拢方向对准一条侧面法线，从侧面贴上去 |
| `touch_toy_2`（恐龙） | `dinosaur_press` | 腕部垂直下压，全程不合指，靠下降产生接触 |
| `touch_toy_3`（软玩具） | `soft_toy_press` | 同样垂直下压；够不着再退到斜贴边缘 |

恐龙那一例最能说明问题。它侧脸几乎是垂直的，贴侧面合指时，指尖沿着闭合圆弧横着扫过去，玩具被推着走，位移超过 2 mm 的保护阈值，按「推倒」处理。改成垂直下压之后，位移落在支撑方向上，零点几毫米就够产生接触。

### 3.7 碰完怎么接下一件

不归位。沿当前腕姿竖直抬起，最多 8 cm，直到连着四帧不再碰到这件玩具，再以同一组实测关节位姿为起点规划下一件：先竖着抬到悬停高度，再横着对齐。

三例动作因此是连着的，末例停在接触位姿，不再抬。

## 四、几个我认为值得一提的设计

**两条判据一起用，才挡得住「擦过」和「推倒」。** 只看物理接触，贴着碰撞外壳蹭过去也会判成功；只看位移，把玩具顶飞了也算碰到。一条管接触质量，一条管接触后果，中间那块假阳性就被挤掉了。本轮三例的分离距离分别是 −0.340 mm、−0.498 mm、−0.002 mm，全是非正值，PhysX 那边判定的是真接触；玩具最大位移 0.15 到 1.61 mm，都在阈值内。

**按形态挑手法，而不是一套参数打天下。** 魔方是平面，适合侧向贴；恐龙侧脸近乎垂直，侧向合指会把玩具扫走；软玩具形状不规整，得留回退路径。三件玩具的失败方式本来就不同，用同一套动作参数，乐观情况是三例里过两例。日志里逐例标了实际生效的 `strategy=`，谁用了哪一手一目了然。

**作答和运行记录绑在一起。** 每次运行落三类结构化产物：`run.json` 记整轮的 outcome、策略、耗时、写入行数与退出状态；`contact-<case>.json` 记接触瞬间的十关节实测值、base/hand/toy 三方位姿、接触刚体对和间隙；`events.jsonl` 记事件流。另有一份 `assets/q3_evidence_index.json` 把作答行和快照对上号。

这么做的理由很实在：物理仿真的结果是一次性的，只留一行 JSON，等于把过程丢了。评审若质疑某一行，可以直接翻到同一时刻的十关节实测值；反过来，从快照的三方位姿也能反算出作答里的两组位姿。这叫可复核，不是「请相信我」。实测三例作答的关节值与快照逐值一致，偏差 0.0 rad；反算出来的位姿，与作答文件相差不到 1e-15 m。

**三例连跑不归位，但把「脱离」变成硬条件。** 连跑省掉两次场景重载，动作也更像真实作业。前提是真的脱离了——所以抬升不是「抬一下就行」，得连续四帧不再接触才算数。带着上一件玩具去够下一件，日志里会表现为非目标接触，事后很难分清是谁的锅。宁可多等两帧，也别留一个来路不明的结果。

## 六、没解决的和不好办的

结果是物理仿真的产物，换机器、换驱动版本不承诺逐字节一致。验收看 `outcome=contact` 和 `visible_surface=touch`。换了 GPU 或驱动，建议先跑单例试水。

三件玩具的姿态是「按形态预设，再有限微调」。换一批形状差异更大的物体，策略表得扩。更通用的路子是从点云或网格自动估接触面法线，这次没做。

判定阈值（6 帧、2 mm 与 6 mm、抬升 8 cm）是本轮实测调出来的。碰上更软或更轻的物体可能偏严，得按材质重新标定。

运行门槛也不低：可用内存 12,800 MiB 起、空闲显存 6,000 MiB 起、驱动 535 到 580。低配机器要么跳过预检，要么走容器路径。
