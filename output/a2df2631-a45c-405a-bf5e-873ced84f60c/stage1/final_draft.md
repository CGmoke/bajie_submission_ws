# 题目二 · 正向运动学与坐标变换：解题思路与创新点

## 一、题目概览

本题要求：根据给定关节状态与官方模型，计算夹爪坐标系 `objects_link` 相对底盘 `base_footprint` 的位姿；再把物体在底盘系中的位姿变换到夹爪坐标系；最终输出两组位姿，并说明运动链读取、坐标变换与姿态表示转换的方法。

| 项目 | 内容 |
|------|------|
| 题号 | 题目二 |
| 题目名称 | 正向运动学与坐标变换 |
| 源码目录 | `src/question2_project/`（`fk.py` 正解 + `solve_q2.py` 入口 + `verify_tf.py` 复核 + 单元测试） |
| 输入 | `inputs/q2_demo_input.jsonl`，公开测例 `demo_zero` |
| 作答 | `answers/q2_demo_output.jsonl`，1 行、两组位姿 |
| 依赖 | 求解只需 Python + NumPy；`--verify` 复核才需要 ROS 2 |

## 二、题面要求与本作品的对应实现

| 题面要求 | 本作品的实现 |
|----------|--------------|
| 根据关节状态和官方模型计算 `objects_link` 相对 `base_footprint` 的位姿 | 解析官方 xacro 展开的 URDF，从 `objects_link` 沿父关节回溯到 `base_footprint`，得到有序关节链并倒序相乘 |
| 将物体在底盘坐标系中的位姿变换到夹爪坐标系 | `T_objects_link^scene = (T_base^objects_link)^-1 · T_base^scene` |
| 说明运动链读取方式、坐标变换过程与姿态表示转换 | 见第三节 3.2 的三个小节 |
| 输出 `id`、两组位姿（`xyz` / `rpy` / `quat_xyzw`） | 字段齐备，四元数写入前归一，`rpy` 与 `quat_xyzw` 互推自洽 |

## 三、解题思路

本节按「总体设计 → 三个关键环节 → 一处关键取舍」展开，重点说明实现里那些「不这么做就会错」的地方。

### 3.1 总体设计

题目本质是**一次刚体变换链的乘法**，难点不在数学，而在三件事：关节链要取对、每段的变换要按 URDF 语义拼对、结果的姿态表示要能自证。

因此设计了一条「自研实现 + 独立第二实现」的双轨路线：

1. **主实现**（`fk.py` + `solve_q2.py`）：不依赖 TF，直接从 URDF 文本解析关节树，自己实现正解与坐标变换；
2. **第二实现**（`verify_tf.py`）：用 ROS 2 的 `robot_state_publisher` + `tf2_ros` 生成同一组位姿，独立进程比对。

两条路线共用同一份 URDF，但代码路径完全不重叠——一条自己算矩阵，一条由 ROS 的 TF 树算。它们同时正确且互相吻合，才有说服力；只跑一条，出错时无从发现。

### 3.2 关键环节

**（1）运动链的读取方式。** 解析 `generated/bajie_robot.urdf`（官方 xacro 展开，`origin` 未改），建立「子连杆 → (父连杆, 关节)」映射；从 `objects_link` 开始沿父关节回溯，直到 `base_footprint`，得到一条有序链，再倒序相乘。

关键细节有三个：

- 每段变换按 `T = T_origin · T_motion(q)` 构造。`T_origin` 来自关节的 `origin` 元素（xyz + rpy，按 Rz·Ry·Rx 展开），`T_motion(q)` 对 prismatic 关节是沿 `axis` 平移 q，对 revolute 关节是绕 `axis` 旋转 q。
- 头部俯仰（`pitch_joint`）与两个夹指是旁支，值要读取但不在这条链上；固定关节没有输入量，仍贡献位置与朝向。
- 模型共 32 个 link、31 个 joint，链上每一段都必须按 URDF 的父子关系取，不能按名字猜顺序。

**（2）坐标变换的计算过程。** 设已知 `T_base^scene`（物体在底盘系的位姿，直接取自输入），已求得 `T_base^objects_link`（夹爪在底盘系的位姿），则物体在夹爪系中的位姿为：

`T_objects_link^scene = (T_base^objects_link)^-1 · T_base^scene`

求逆时用旋转矩阵转置加平移反投影（`R^T`, `-R^T t`），而不是通用 4×4 求逆——刚体变换的逆有解析形式，这样既快又不会引入数值误差。

**（3）姿态表示的转换。** 内部统一用 4×4 齐次矩阵运算，只在输出时转成 `rpy` 与 `quat_xyzw`：

- `rpy`：`pitch = asin(−R20)`，`roll = atan2(R21, R22)`，`yaw = atan2(R10, R00)`；
- `quat_xyzw`：由旋转矩阵转四元数，按 `[x, y, z, w]` 顺序输出，写入前归一。

两组位姿的 `rpy` 与 `quat_xyzw` 必须互相自洽——这是本题最容易出错的地方（四元数顺序写反、未归一、`rpy` 用错旋转顺序），所以校验阶段专门做了互推比对。

### 3.3 关键取舍：为什么不用 TF 直接求

最省事的做法是启动 `robot_state_publisher`，用 `tf2_ros` 查询 `base_footprint → objects_link` 的变换，一行代码就能出结果。这里没有采用，原因有三：

1. 题面要求「说明运动链的读取方式」——用 TF 会把这段逻辑藏进 ROS 内部，等于不答；
2. TF 需要 ROS 运行时，而题目只要求「根据关节状态和官方模型计算」，纯计算不该有运行时依赖；
3. 用 TF 求解时，一旦结果不符合预期，无法判断是模型加载错了还是自己算错了。

于是把 TF 放到「第二实现」的位置：它不参与产出，只负责打脸或背书。

## 四、创新点

四条创新点围绕「算得对、自证得了、写得出去、跑得起来」展开，每条附对应的验证数据。

### 创新点一：自研正解与 TF2 交叉验证，两种实现互相印证

**做法**：`fk.py` 自己解析 URDF 算矩阵；`verify_tf.py` 用独立进程的 `robot_state_publisher`（`frame_prefix=q2_verify/`）生成参考值，再与主实现比对，阈值 `1e-8 m` / `1e-7 rad`。

**为什么更好**：单一实现只能证明「跑通了」，两种独立实现同时吻合才能证明「算对了」。而且两套实现的失效模式不同——自己写错矩阵乘法、TF 读错帧名，两者不会同时发生。

**证据**：三组用例（正式零位、仅 `lift_joint +0.1 m`、弯曲臂且物体带 `rpy=[0.2,−0.3,0.5]`）的位置与旋转误差均在 **1e-15** 量级，远低于阈值。

### 创新点二：把「位姿链自洽」做成可复算的判据

**做法**：除题目要求的两个输出外，再用它们反推一次：`T_base^scene = T_base^grip · T_grip^scene`，与输入的 `scene_object_in_base_footprint` 逐项比对。

**为什么更好**：题目给的两组位姿之间存在天然的等式约束。若实现里把变换方向写反（乘了正变换而非逆变换），单看某一组数值可能「看起来合理」，但这条等式会立刻崩掉。把它写进校验，等于给答案加了一条不依赖外部基准的自检。

**证据**：位置误差 0.0 m，旋转矩阵误差 1.9e-19；`rpy` 与 `quat_xyzw` 互推最大差 2e-19 rad。

### 创新点三：输出前的格式门禁，把常见错误挡在写文件之前

**做法**：每一行作答在写出前检查三件事——关节名齐全、位姿三个字段长度正确、四元数模长为 1；任一不满足就整轮中止且不覆盖旧作答。

**为什么更好**：JSONL 格式错误是这类题最容易被判 0 分的死法（少个字段、多个逗号、四元数没归一）。把校验放在写文件之前，错误在本地就暴露，而不是在评审打开文件时。

**证据**：三组位姿的四元数模长实测 1.000000000000；作答 SHA-256 为 `98fd3d80…2474cc37`。

### 创新点四：求解与复核解耦，纯计算不依赖 ROS 运行时

**做法**：`solve_q2.py` 只用 Python + NumPy，`--verify` 才引入 ROS。

**为什么更好**：评审在没装 ROS 的环境里也能复现作答；装了 ROS 的人可以多做一层验证。同一份代码服务两种场景，而不是要求所有人先装一整套 ROS。

**证据**：`--verify` 与否产出的作答完全一致（同一 NumPy 版本下逐字节相同）。

## 五、验证结果

| 验证项 | 结果 |
|--------|------|
| 输出字段 | `id`、`objects_link_in_base_footprint`、`scene_object_in_objects_link` 齐备 |
| 姿态表示 | 两组位姿均含 `xyz` / `rpy` / `quat_xyzw`；四元数模长 1.000000000000 |
| TF2 复核误差 | 三组用例均 < 1e-15（阈值 1e-8 m / 1e-7 rad） |
| 位姿链自洽 | `T_base^scene = T_base^grip · T_grip^scene` 位置误差 0.0 m，旋转 1.9e-19 |
| 作答可复现性 | 同 NumPy 版本逐字节一致，SHA-256 `98fd3d80…2474cc37`；跨版本仅 1e-19 量级末位差异 |
| 运行耗时 | 求解 < 5 s |

## 六、局限与改进方向

- 只支持 revolute / prismatic / fixed 三类关节与 mesh、box、cylinder、sphere 四类几何；遇到 URDF 中罕见的 `planar`、`floating` 关节需要扩展。
- 平坦零位附近 `rpy` 的 `yaw` 对数值噪声敏感（本例 `rpy` 的 yaw 在 1e-8 量级），若下游要按 `rpy` 做阈值判断，建议改用四元数或旋转矩阵。
- 模型若有 `mimic` 关节（如联动指），当前实现按「输入已给出每个关节的实际值」处理，不做联动推导；题面给了全部 10 个关节值，因此不构成问题，但扩展到只给部分关节时会失效。
